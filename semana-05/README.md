# Semana 5 — Casos, execução e bugs

7h–8h: conceitos; 8h–10h: exemplos guiados; 10h–12h: cenários e prática; 12h–13h: almoço; 13h–15h: investigação e registros; 15h–16h: discussão e entrega.

Execute os casos planejados primeiro em `semana-04/login.js`, sem consultar a correção. Registre entrada, esperado, obtido, status e evidência identificada por caso. Um caso bloqueado não é um caso aprovado.

Use o modelo de bug para descrever o problema de campos vazios. Defina severidade pelo impacto e prioridade pela urgência de correção.

Depois leia `login-corrigido.js` e execute `node semana-05/demonstracao.js` para comparar as versões. Reteste o caso que falhou e faça regressão nos casos que já passavam.

Fluxo sugerido: Aberto → Em correção → Corrigido → Em reteste → Fechado. Se persistir, Reaberto. Marcar como corrigido não dispensa reteste.

Prática: entregue a tabela executada, evidências reais, bugs e situação atual. Use `docs/exemplo-login.md` como referência de formato, sem copiar seus resultados como evidência própria.
